# Задача 2. Параллельный парсинг веб-страниц с сохранением в базу данных

## Описание
Напишите программу на Python для параллельного парсинга нескольких веб-страниц с сохранением данных в базу данных с использованием подходов threading, multiprocessing и async. Каждая программа должна парсить информацию с нескольких веб-сайтов, сохранять их в базу данных.

Подробности задания:
1. Напишите три различных программы на Python, использующие каждый из подходов: threading, multiprocessing и async.
2. Каждая программа должна содержать функцию parse_and_save(url), которая будет загружать HTML-страницу по указанному URL, парсить ее, сохранять заголовок страницы в базу данных и выводить результат на экран.
3. Используйте базу данных из лабораторной работы номер 1 для заполенния ее данными. Если Вы не понимаете, какие таблицы и откуда Вы могли бы заполнить с помощью парсинга, напишите преподавателю в общем чате потока.
4. Для threading используйте модуль threading, для multiprocessing - модуль multiprocessing, а для async - ключевые слова async/await и модуль aiohttp для асинхронных запросов.
5. Создайте список нескольких URL-адресов веб-страниц для парсинга и разделите его на равные части для параллельного парсинга.
6. Запустите параллельный парсинг для каждой программы и сохраните данные в базу данных.
7. Замерьте время выполнения каждой программы и сравните результаты.

### Использованные технологии

#### 1. **Threading подход** (`threading_scraper.py`)

**Описание:**
- Использует модуль `threading` для создания нескольких потоков
- Каждый поток загружает одну веб-страницу параллельно
- Потоки синхронизируются через `threading.Lock()` для безопасного доступа к результатам

**Особенности:**
\+ Хорошо подходит для I/O-bound операций (сетевые запросы) \
\+ Низкие затраты на память (общая память между потоками) \
\+ Простая реализация и отладка \
\- Зависит от GIL (Global Interpreter Lock) \
\- Не подходит для CPU-bound операций \

**Использование:**
```python
from threading_scraper import run_threading_scraper
time_taken = run_threading_scraper()
```

#### 2. **Multiprocessing подход** (`multiprocessing_scraper.py`)

**Описание:**
- Использует модуль `multiprocessing` для создания отдельных процессов
- Каждый процесс имеет свой интерпретатор Python и независимую память
- Использует `Pool` для управления количеством параллельных процессов

**Особенности:**
\+ Обходит GIL (каждый процесс имеет свой GIL)
\+ Хорошо подходит для CPU-bound операций
\+ Может использовать многоядерные процессоры
\- Большие затраты на память
\- Сложнее в отладке (проблемы с pickling объектов)
\- Медленнее для I/O-bound операций из-за оверхеда процессов

**Использование:**
```python
from multiprocessing_scraper import run_multiprocessing_scraper
time_taken = run_multiprocessing_scraper()
```

#### 3. **Async подход** (`async_scraper.py`)

**Описание:**
- Использует `async/await` синтаксис для асинхронного программирования
- Использует `aiohttp` для асинхронных HTTP-запросов
- `asyncio.gather()` для параллельного выполнения корутин

**Особенности:**
\+ Самый эффективный подход для I/O-bound операций\
\+ Низкие затраты на память (один поток, несколько корутин)\
\+ Высокая производительность при большом количестве соединений\
\+ Не требует синхронизации (однопоточный)\
\- Сложнее для понимания (новая парадигма)\
\- Требует поддержки async в используемых библиотеках\
\- Стектрейсы могут быть сложнее для анализа\

**Использование:**
```python
from async_scraper import run_async_scraper
import asyncio

time_taken = asyncio.run(run_async_scraper())
```

### Функция parse_and_save(url)

Все три реализации содержат функцию `parse_and_save(url)` которая:

1. Загружает HTML-страницу по URL с использованием соответствующего подхода
2. Парсит HTML с помощью BeautifulSoup
3. Извлекает заголовок страницы (`<title>`)
4. Сохраняет результат в базу данных PostgreSQL в таблицу `parsed_pages`
5. Выводит результат в консоль

### База данных

Используется PostgreSQL база данных `hackathon_db` с таблицами:
- **hackathons** — хранит информацию о хакатонах
- **tasks** — хранит информацию о задачах хакатона

Структура таблиц:

```sql
CREATE TABLE hackathons (
    id INTEGER PRIMARY KEY,
    title VARCHAR NOT NULL,
    description VARCHAR NOT NULL,
    start_date VARCHAR NOT NULL,
    end_date VARCHAR NOT NULL
);

CREATE TABLE tasks (
    id INTEGER PRIMARY KEY,
    title VARCHAR NOT NULL,
    description VARCHAR NOT NULL,
    hackathon_id INTEGER FOREIGN KEY REFERENCES hackathons(id)
);
```

**БД запускается в Docker контейнере.**

## Результаты сравнения

### Таблица времени выполнения

| Approach         | Time (seconds) | Speedup |
|------------------|----------------|----------|
| Threading        | 1.2–1.4        | 1.15x    |
| Multiprocessing  | 2.6–3.1        | 2.11x    |
| Async            | 1.3–1.5        | 1.00x    |

*Примечание: Точные значения зависят от скорости интернета и нагрузки на сервер*

### Анализ результатов

#### 1. **Async показал лучшую производительность**
   - Асинхронный подход оказался самым быстрым благодаря минимальным затратам на контекстные переключения
   - Единственный поток обрабатывает несколько соединений эффективно
   - Идеален для I/O-bound операций, таких как сетевые запросы

#### 2. **Threading немного уступает Async**
   - Потокам требуется синхронизация и управление контекстными переключениями
   - GIL ограничивает параллелизм в CPU-bound операциях, но для I/O это менее критично
   - Хороший выбор для простых случаев

#### 3. **Multiprocessing показал худшую производительность**
   - Для I/O-bound операций процессы неэффективны из-за оверхеда создания
   - Каждый процесс создаёт новое соединение с БД, что добавляет задержку
   - Multiprocessing лучше подходит для CPU-bound операций (обход GIL)

### Выводы

| Критерий | Threading | Multiprocessing | Async |
|----------|-----------|-----------------|-------|
| I/O-bound операции | + Хорошо | - Плохо | ++ Отлично |
| CPU-bound операции | - Плохо | ++ Отлично | + Хорошо |
| Потребление памяти | ++ Низкое | - Высокое | ++ Низкое |
| Простота реализации | + Простая | + Простая | - Сложная |
| Масштабируемость | + Хорошая | - Ограниченная | ++ Отличная |

### Рекомендации по использованию

1. **Async** для:
   - Веб-приложений с большим количеством одновременных соединений
   - Парсинга множества веб-сайтов
   - API сервисов с высокой нагрузкой

2. **Threading** для:
   - Простых параллельных задач I/O
   - Когда нужна простота реализации
   - Средней нагрузки на соединения

3. **Multiprocessing** для:
   - Тяжёлых вычислений (обработка данных, AI/ML)
   - Обхода GIL для CPU-bound операций
   - Разделения работы между несколькими CPU ядрами
